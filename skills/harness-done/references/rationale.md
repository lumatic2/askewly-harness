# harness-done — 규칙의 경위

SKILL.md 는 지시만 둔다. 날짜·실측이 붙은 경위는 여기.

- **코드 리뷰 자리는 하나다** — 자체 에이전트는 2026-09-22 ADR 0033(구 h-e ADR 0015)로 코드 리뷰에서 떼어내 4단계 마감 감사자가 됐다. 「두 자리」 문구를 되살리지 말 것.
- **지적 기각은 정상 처분** — 2026-09-21 메모: 리뷰 지적을 무비판 반영해 맞던 것을 틀리게 바꾼 사례가 여럿이었다.
- **스위트를 1단계로** (2026-11-16) — 노트 뒤에서 돌리면 실패 수정 커밋이 노트의 `검증:`·`실표면:` 을 낡게 만들었다. 최근 30일 done 세션 62개 중 22개가 `report_close` 를 두 번 이상 불렀다.
- **§3 자동 블록** (2026-11-16) — 30일 마감 감사 77건의 막는 지적 225건 중 141건이 노트 수기 오류였다(수치 불일치 33·범위 초과 주장 30·낡은 리비전 증거 29·DoD 미충족 25·마감 기록 누락 24 — custom-skills `changesets/20261113-audit-third-batch.md`).
- **감사 스폰을 계획서가 정한다** (2026-11-16 사용자 결정) — 구 조건 「step ≥3」은 거의 항상 참이라 66세션에 74회 스폰됐다(회당 중앙 6.3분·출력 5만 토큰). 계획 승인 때 사용자가 고른다. 결정 기록 a-o `docs/adr/0039-done-thinning.md`.
- **연쇄 계획서에 plan-verifier 없음** (2026-11-16 사용자 결정) — 참고용·막지 않음이었고 반영률 97%, 회당 중앙 7.4분·출력 7.7만 토큰. `approve_harness_plan.py --chained-from` 의 「검증 처분 필수」도 함께 폐지.
- **연쇄 마감은 약식** (2026-11-16 사용자 결정 — 당시 이름 `/session-end --chain`) — 연쇄 세션마다 끝내기 모드 전체(문서 위생·CLAUDE.md 점검·요약)를 돌던 컨텍스트 낭비. 연쇄 뒤 구간이 메인 도구 호출 중앙 52회였다. 2026-11-18 `--relay`(넘기고 마감)로 흡수되며 순서가 「발사 → 마감」에서 「HANDOFF 병합·push → 발사」로 바뀌었다 — 일반 이월과 진입점을 하나로 합친 사용자 결정.
- **`감사:`·`리뷰:` 줄은 미평가 탐지에서 뺀다** (2026-11-16) — `감사: none — …` 에 조건 이름 「평가 못 함」을 적었다가 거부되던 함정(2026-09-22 실측)을 경고문 대신 코드로.
- **리뷰는 상시 한 자리, 명세 3질문은 감사 안 할 때만** (2026-11-16 사용자 결정) — 「closing-auditor 하나만」을 검토했으나 최근 완료 노트 82건에서 리뷰가 62번 돌며 대개 지적 10건 중 3~9건이 실제 수리(경합·경로 탈출 등 정확성 결함)였고, 감사자는 정의상 정확성을 판별하지 않는다. 겹침은 10-14 에 리뷰에 얹은 명세 3질문뿐이라 그것만 감사 유무로 가른다.
- **리뷰를 띄우고 스위트를 함께** (2026-11-16) — 리뷰 실행은 중앙 2.0분(high 4.4분)으로 짧고 백그라운드로 돈다. 병목은 지적 반영 구간(중앙 6.8분·도구 16회, 상위 25% 12.7분·26회)이었다.
- **리뷰 강도 medium 고정 · 확인된 지적은 마감 안에 전부 고친다** (2026-11-17 사용자 결정) — high 는 리뷰 실행이 중앙 4.4분으로 medium(1.7분)의 약 2배였고 필요한 경우가 없었다. 이월(노트 §2·finding 큐)을 허용하면 결함이 다음으로 밀려 남는다 — 「깔끔한 게 좋다」.
