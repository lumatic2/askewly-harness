세션을 마무리한다. 세 모드 — **끝내기**(기본) · **`--checkpoint`**(중간 저장) · **`--relay`**(넘기고 마감 — 마감한 뒤 새 세션을 띄워 일을 잇게 한다. 2026-11-18, 구 `--chain` 을 흡수). 하는 일은 다섯, 이 순서다: **문서 위생**(끝내기·직접 부른 `--relay`), **데이터 레포 점검**(끝내기·`--relay` — 약식 `--relay` 는 점검·push 만. 6축 인입은 사용자가 넣으라고 한 것만), **HANDOFF.md 병합**(전부 — 레포 공용 할 일 큐에 항목 단위로 — 쓰는 일의 맨 끝, 마감당 한 번), **새 세션 발사**(`--relay` 만 — HANDOFF push 뒤), **채팅 요약**(끝내기·직접 부른 `--relay`, 저장하지 않는다). Tasks 대조·저널 요약 저장은 하지 않는다 — 세션 **원문**은 Stop 훅(`session_archive.py capture`)이 매 세션 `$HARNESS_JOURNAL_DIR`/agent-sessions/` 에 자동으로 쌓는다(요약 저장 중단, 원문은 영구).

```bash
# 둘 다 ~/.claude 우선 — Claude 쪽은 소스 정션이라 가장 새것이고, 없는 기기(Codex 전용)만 ~/.codex 사본을 쓴다
ASKEWLY_ROOT="${CLAUDE_PLUGIN_ROOT}"; [ -d "$ASKEWLY_ROOT/skills" ] || ASKEWLY_ROOT="$(ls -d "${CODEX_HOME:-$HOME/.codex}"/plugins/cache/*/askewly/*/ 2>/dev/null | tail -1)"
HARNESS_SCRIPTS="${ASKEWLY_ROOT%/}/skills/harness-run/scripts"
SE_BIN="${ASKEWLY_ROOT%/}/skills/session-end/bin"
HARNESS_ROOT="$(python "$HARNESS_SCRIPTS/harness_focus.py" resolve)"   # 초점 없으면 cwd
```

HANDOFF 기록처 = `$HARNESS_ROOT`. 이 세션이 초점을 다른 레포에 두고 일했으면 HANDOFF 는 그 레포에 쓴다. **linked worktree 세션도 이제 HANDOFF 를 쓴다** — `handoff_merge.py` 가 main 체크아웃을 스스로 찾아 그 파일에 항목 단위로 병합하고, `handoff_commit.sh` 도 main 에서 커밋한다(구 「워크트리는 plan doc 진행 로그만」·`--to-main` 메모 경로는 폐지). 할 일 수명은 날짜다 — 14일 동안 추가·수정이 없으면 레포 백로그 「오래된 할 일」로 내려간다(§3).

**`--relay` — 넘기고 마감** (2026-11-18 사용자 결정). 순서는 고정이다: **HANDOFF 병합·push → 시작 프롬프트 → 새 세션 발사 → 요약**. HANDOFF 가 먼저 원격에 올라가야 새 세션의 SessionStart 주입이 방금 병합한 큐를 읽고, 발사가 실패해도 인계를 잃지 않는다. 마감의 무게는 부른 쪽에 따라 갈린다:

| 부른 쪽 | 마감 | 발사(§3b) | 끝 |
|---|---|---|---|
| **사용자가 직접** — 「넘기고 마감」·「새 세션에 넘기고 마감」·「새 세션 켜고 마감」·`/session-end --relay` | 끝내기 전부(§1·§1b·§2·§3) | 이 스킬이 시작 프롬프트와 모델을 정해 띄운다 | §4 요약 |
| **하네스 스킬** — `/harness-plan` `새로ㄱ`, `/harness-done` §6 연쇄 | 약식 — §2 의 점검·push(인입은 이 세션에서 사용자가 「넣어 줘」라고 한 것이 남았을 때만 — 무인 연쇄에는 없다)와 §3 뿐 | 그 스킬이 넘긴 발사 명령을 그대로 실행한다 | 한 줄 |

`handoff_commit.sh` 는 두 경우 모두 **push 포함**이다(`--checkpoint` 와 다르다). 약식이 §1 문서 위생·§1b CLAUDE.md 점검·§4 채팅 요약을 건너뛰는 이유 — 일을 넘겨받은 쪽(목표가 끝난 연쇄 세션, 발사된 실행 세션)이 끝날 때 끝내기 모드로 레포 전체를 한 번 본다(연쇄 세션마다 반복하던 컨텍스트 낭비, 2026-11-16 사용자 결정).

구 `--chain`(발사한 **뒤에** 부르던 약식)은 이 모드에 흡수됐다. 옛 문구를 기억한 세션이 발사 뒤에 `--chain` 으로 부르면 약식 `--relay` 에서 발사만 빼고 한다.

## 0. 출력 계약

**session-end 는 세션의 마지막에 입력된다. 출력에 사용자가 할 일이 있으면 안 된다.** 처분이 필요한 발견은 HANDOFF 할 일로 쓴다 — 묻거나 제안하지 않는다. 판정 한 줄: "사용자가 지금 답해야 무언가가 진행되는가?" — 예이면 그것은 HANDOFF 항목이다. `--checkpoint` 는 세션이 계속되므로 이 계약이 느슨하다 — 병합한 뒤 하던 일로 돌아간다. 예외는 하나 — `--relay` 의 발사가 끝내 착지하지 않았을 때 시작 프롬프트 본문을 요약에 싣는 것(§3b).

## 1. 문서 위생 — 검사 → 기계적 수정 → 못 고친 것만 기록 (끝내기 · 직접 부른 `--relay`)

검사기는 **레포가 가진 것만** 쓴다. `$HARNESS_ROOT/scripts/doc_drift_check.py` 가 있으면 실행하고, 없으면 이 절은 통째로 건너뛴다(없는 검사기를 만들지 않는다).

```bash
[ -f "$HARNESS_ROOT/scripts/doc_drift_check.py" ] && (cd "$HARNESS_ROOT" && python scripts/doc_drift_check.py)
```

**고치는 것은 아래 두 종류뿐이다.** 그 밖은 손대지 않는다 — 판단이 섞이는 순간 마감이 작업으로 번진다.

1. **`[stale-view]` 생성 뷰 stale** → 그 뷰의 생성기를 `render` 로 다시 돌린다. 검사기 출력이 생성기를 알려 주지 않으면 고치지 말고 2 로 보낸다.
2. **`[dead-path]` 인데 접두만 누락된 경우** → 백틱 안 경로의 basename 이 레포 안에 **정확히 한 곳에만** 실재할 때에 한해 그 경로로 교정한다. 두 곳 이상이거나 아예 없으면 고치지 않는다.

고친 게 있으면 **고친 파일만 pathspec 으로 별도 커밋**한다(`chore(hygiene): <한 줄>`). 못 고친 findings 는 HANDOFF 할 일로 경로와 함께 한 줄씩 쓴다(고칠 행동으로).

ROADMAP 위생은 읽기 전용으로 한 번 본다 — `python3 "$SE_BIN/roadmap_hygiene.py"`(항상 exit 0). 발견이 있으면 고치지 않고 HANDOFF 할 일로 한 줄 쓴다(고칠 행동으로 — 같은 발견은 본문이 같아 하나로 합쳐진다).

### 1b. 레포 `CLAUDE.md` 생존 점검 (끝내기 · 직접 부른 `--relay`)

레포 `CLAUDE.md` 는 살아 있는 문서인데 부트스트랩 뒤 아무도 다시 안 봤다. 마감이 「이번 세션에서 무엇이 바뀌었나」를 아는 유일한 시점이라 여기서 본다. 대상은 `$HARNESS_ROOT/CLAUDE.md` 하나 — 「북극성」 절과 글로벌 `~/.claude/CLAUDE.md` 는 보지 않는다. 기준은 `the-orchestration-repo/docs/harness/10-context-wording.md` §2(커스텀만 남긴다).

먼저 스크립트를 돌린다 — 첫 질문은 기계가 본다:

```bash
python3 "$SE_BIN/claude_md_check.py" --root "$HARNESS_ROOT"    # 마지막 HANDOFF 커밋 뒤의 삭제·이동을 CLAUDE.md 백틱 경로와 대조, 항상 exit 0
```

**완료 메시지의 `CLAUDE.md 점검` 칸에는 이 출력의 판정을 옮긴다.** 스크립트를 안 돌렸으면 `건너뜀` 이라고 쓴다 — 보지 않고 「변경 없음」이라 쓰지 않는다. 출력을 놓고 세 가지를 본다:

1. **CLAUDE.md 가 가리키는 것이 사라지거나 옮겨졌나** — 스크립트가 `…가 삭제됐다`·`…로 옮겨졌다` 를 찍은 줄만 본다(`닿는 것 없음` 이면 끝). 옮겨졌고 새 위치가 레포 안에 **정확히 한 곳**이면 경로를 교정한다(§1 의 2 와 같은 규칙). 삭제됐으면 고치지 않고 할 일로.
2. **이 세션이 만든 것 중 CLAUDE.md 가 몰라도 되는가** — 새 스크립트·새 플래그·새 금지사항·새 폴더가 생겼으면, 「다음 세션이 코드만 보고 알 수 있는가」로 가른다. 알 수 없는 것만 할 일로 적는다. **추가는 하지 않는다**(무엇을 남길지는 판단이라 사람 몫).
3. **이 세션에서 같은 교정을 두 번 받았나** — 있으면 그 문구를 할 일로 적는다(「CLAUDE.md 추가 제안: …」). 2회 교정 규칙은 그 자리에서 제안하는 것이 원칙이고, 여기는 놓친 것을 줍는 그물이다.

고치는 것은 1 의 경로 교정뿐이고, 고쳤으면 `chore(hygiene): CLAUDE.md 경로 교정 <한 줄>` 로 pathspec 커밋한다. 2·3 은 HANDOFF 「이어서 할 일」에 `CLAUDE.md 갱신 후보: <한 줄> — 근거 <커밋>` 으로 적는다(§0 — 묻지 않는다). 셋 다 없으면 한 줄도 안 쓴다.

## 3. HANDOFF.md — 레포 공용 할 일 큐에 항목 단위로 병합 (전부 · 마감당 한 번)

`HANDOFF.md` 는 세션 간 인계 문서다. git-tracked 라 다른 기기의 다음 세션도 같은 것을 읽고, SessionStart 훅이 **그 레포의 모든 세션에** 자동 주입한다 — 그래서 무엇을 쓰느냐가 매 세션의 비용이다. 주입되는 것은 「이어서 할 일」 전부 · 「기다리는 일」 중 날짜가 된 것과 대기 건수 한 줄 · 「최근 작업」 줄 수 한 줄이다(본문은 2026-11-13 부터 주입하지 않는다 — 파일에서 읽는다). 압축 직후에는 포인터 한 줄과 날짜가 된 기다리는 일만 싣는다. `/briefing` 은 「이어서 할 일」 첫 항목을 그 레포의 「다음 할 일」로 싣고, 레포 백로그 건수를 줄 끝에 붙인다.

**할 일은 레포 공용 큐다**. 세션이 끝나면 다음 일은 언제나 다른 세션이 한다 — 할 일의 주인은 세션이 아니라 레포다. 할 일 줄 끝의 `(날짜 · 작업 이름)` 은 출처 표시일 뿐 소유가 아니다. **어느 세션이든 끝냈거나 해소 커밋을 확인한 할 일은 근거를 달아 뺀다.** 병합은 항목 단위(추가·완료·수정)라 동시에 마감해도 서로 덮어쓰지 않는다 — Write 로 전체를 덮어쓰지 않는다. 세션 자신은 「최근 작업」 한 줄만 남긴다(상세는 git log·세션 원문). **병합·커밋은 마감에 한 번** — §1·§2 를 다 끝낸 뒤에 한다. 다시 돌려도 안전하다(같은 본문 추가는 아무 일도 안 하고, 같은 작업 이름의 최근 작업 줄은 교체된다).

**작업 이름**(`--tag`) = 계획서 slug·워크트리 브랜치·`main` 등(`·` `[` `]` `(` `)` 금지). 최근 작업 줄과 새 할 일의 출처 표시에 쓰인다.

읽을 것: 기존 `HANDOFF.md` 의 「이어서 할 일」·「기다리는 일」 전부(이 세션이 끝낸 것을 찾는다), 열린 계획서.

**할 일은 쓰기 직전에 현재 HEAD 로 다시 확인한다** (세션 초반에 본 줄번호는 이미 해소됐을 수 있다). 파일·줄을 인용하면 그 줄이 지금도 그 내용인지, `git log --oneline --since=<세션 시작> -- <그 파일>` 에 해소 커밋이 없는지 본다. 이미 끝났으면 쓰지 않는다.

```bash
python3 "$SE_BIN/handoff_merge.py" --root "$HARNESS_ROOT" --tag <작업 이름> --pull <<'IN'
- {지금 할 수 있는 다음 행동, 동사로 끝남 — 착수 지점(커맨드·파일·plan step) 포함}
- ⏳ {YYYY-MM-DD 가 든 조건} — {그때 할 행동}       ← 「기다리는 일」 (그 날짜 + 7일까지 산다)
- ⏳ {날짜 없는 조건} — {그때 할 행동}              ← 레포 백로그 「기다리는 일」로 간다 (커밋 헬퍼가 같은 커밋에 넣는다)
완료: {할 일 일부} = {근거 — 커밋 해시 등}           ← 누가 넣은 할 일이든. 근거는 핸드오프 커밋 메시지에 남는다
수정: {줄을 찾는 조각} => {그 줄을 통째로 대체할 전체 문구}   ← 문구가 낡았을 때. 부분 치환이 아니다 — 매칭된 줄 전체가 오른쪽 문구로 바뀐다(왼쪽 조각은 사라진다). 날짜가 오늘로 바뀐다
                                                         예) 수정: 린트 고친다 => 린트를 고치고 CI 에서 확인한다
## 최근 작업
- {커밋: 레포별 최종 해시 · push 여부 · 이 세션이 남긴 미커밋만 — 한 줄, 160자에서 잘린다}
IN
```

`완료:`·`수정:` 은 본문 기준 **정확히 1건** 일치할 때만 적용된다(같은 본문이 여러 줄이면 한꺼번에). `못 뺐다 … N건`·`수정 못 했다` 가 찍히면 더 긴 일부로 다시 돌린다. 근거 없는 `완료:` 는 거부된다 — 근거가 없거나 애매하면 두고 넘긴다. `--resolve '<일부>=<근거>'` 는 `완료:` 의 별칭이다.

**할 일은 세 갈래다** (지금 손댈 수 없는 일을 매 세션이 읽지 않게 가른다):

| 갈래 | 쓰는 곳 | 판정 |
|---|---|---|
| 지금 할 일 | `- 행동` | 다음 세션이 바로 손댈 수 있다 |
| 날짜를 기다리는 일 | `- ⏳ 2026-12-07 이후 — 행동` | 깨는 조건이 날짜다. 날짜 전엔 건수 한 줄로만 보인다 |
| 날짜 없이 기다리는 일 | `- ⏳ PR #38118 머지되면 — 행동` | 깨는 조건이 사건·누적·남의 작업이다. 스크립트가 레포 `docs/BACKLOG.md` 「기다리는 일」 절로 보낸다 — 항상 읽히지 않고, 필요할 때 읽는다 |
| **쓰지 않는다** | — | 지켜보는 장치가 이미 있다 — OSS 메인테이너 응답은 브리핑 「상류 응답」 줄(`oss_followup.py`)이 매번 본다(만료 38건 중 14건이 이 중복이었다) |

**수명은 스크립트가 정한다**: 할 일은 14일 동안 추가·수정이 없으면 백로그 「오래된 할 일」로 내려간다(같은 본문을 다시 넣는 것은 「건드림」이 아니다 — 날짜가 그대로다). 기다리는 일은 조건 날짜 + 7일이 지나면 같은 곳으로. 최근 작업 줄은 7일. 「만료」 절은 없다. 옛 형식(세션 블록·단일 문서) HANDOFF 는 병합할 때 한 번 새 형식으로 옮겨진다.

병합기가 백로그를 바꾸면(`백로그 N건 추가 …`) 그 경로를 `<git-dir>/HANDOFF_WITH` 에 남기고 커밋 헬퍼가 같은 커밋에 넣는다 — `--with` 를 따로 줄 필요 없다. 같은 체크아웃의 동시 마감은 `<git-dir>/HANDOFF.lock` 으로 줄을 선다. `지켜보는 장치 … 쓰지 않는다` 나 `다른 레포(…) 할 일로 보인다` 경고가 찍히면 그 줄을 `완료: <일부> = 다른 레포로 옮김` 으로 빼고, 다른 레포 일은 그 레포에서 `--root <그 레포>` 로 병합·커밋한다.

규칙:
- 할 일을 적기 전에 줄마다 소속 레포를 정한다 — 그 일을 실제로 할 파일이 어느 레포에 있는가. 이 레포가 아니면 이 레포 HANDOFF 에 적지 않고 `--root <그 레포>` 로 그 레포에 병합·커밋한다. 어느 레포인지 못 정하면 이 레포에 적고 줄 끝에 `(소속 확인 필요)` 를 붙인다.
- 때는 **날짜나 조건**으로 쓴다 — 「내일」·「다음 설치 때」처럼 쓰면 언제 읽느냐에 따라 뜻이 바뀐다. `2026-11-08 전에`·`pnpm 다음 버전이 나오면` 식으로.
- 할 일에는 **행동**만. 상태 서술·회고는 쓰지 않는다(최근 작업 줄은 커밋 포인터 한 줄). 이월 꼬리(`(날짜 · 작업 이름)`·`[태그]`)는 스크립트가 뗀다.
- 최근 작업 줄에 남의 세션·남의 레포 상태(다른 세션의 미커밋 파일·다른 레포의 미커밋 개수)를 쓰지 않는다 — 갱신할 주체가 없어 쓰는 순간 낡는다(`references/rationale.md` ④). 방치된 것은 §2 규칙대로 할 일 한 줄. 열린 계획서가 있으면 계획서 자체가 진행 장부다 — 다음 step 은 할 일 한 줄로 쓴다(`/harness-run` 으로 <계획서> 의 첫 미체크 step 부터 잇는다).
- 훅이 계산하는 것(경과일수 등)을 복사하지 않는다. 기기-로컬 사실은 `CLAUDE.local.md`(gitignored) 로. 다른 레포의 일은 그 레포의 HANDOFF 에 직접.

커밋+push 는 헬퍼가 한다 — HANDOFF.md(와 `--with` 경로)만 pathspec 커밋. 병합기가 남긴 완료 근거(`<git-dir>/HANDOFF_COMMIT_MSG`)를 커밋 메시지 본문에 싣고 지운다. 커밋이 훅에 거부되면 훅 출력 끝 40줄이 stderr 의 `[handoff]` 줄로 나온다(우회 env 는 헬퍼가 주지 않는다 — 레포 정책이다) — 원인을 고치고 다시 돌린다(근거 파일은 남아 있다). `--checkpoint` 는 `--no-push`(로컬 커밋만 — push 는 끝낼 때). push 실패는 경고만. **원격보다 앞선 커밋에 `chore(handoff)`·`chore(hygiene)` 밖의 것이 섞이면 push 를 보류하고 목록을 찍는다**(`git push` 는 브랜치 전체를 올려 다른 세션의 리뷰 전 커밋까지 올라갔다). 목록이 전부 이 세션 커밋이면 `--push-all` 로 다시 돌리고, 아니면 그대로 둔다(그 세션이 push 할 때 함께 올라간다) — 완료 줄에 `push 보류` 로 적는다:

```bash
bash "$SE_BIN/handoff_commit.sh" --root "$HARNESS_ROOT"              # 끝내기 · --relay
bash "$SE_BIN/handoff_commit.sh" --root "$HARNESS_ROOT" --no-push    # --checkpoint
bash "$SE_BIN/handoff_commit.sh" --root "$HARNESS_ROOT" --push-all   # 보류 목록이 전부 이 세션 것일 때만
```

## 4. 채팅 요약 (끝내기 · 직접 부른 `--relay` — 저장하지 않는다)

최종 답변 본문에 직접 쓴다. 파일로 남기지 않는다 — 원문은 Stop 훅이, 인계는 HANDOFF 가 맡는다.

```
한 일 — {무엇이 실제로 바뀌었는지, 커밋·경로·검증 결과를 붙여 3~7줄}
넣은 것 — {사용자가 넣으라고 해서 넣은 항목: 축 · id · 레포 커밋. 없으면 이 줄을 뺀다}
넘긴 곳 — {`--relay` 만: 새 탭 핸들 · 모델(근거 한 줄) · 착지 | 발사 실패 — 사유 + 시작 프롬프트 본문 코드 블록. 그 밖엔 이 줄을 뺀다}
남긴 일 — {이번 병합에서 추가한 할 일 · 완료로 뺀 할 일 echo}
판단 필요 — {사용자가 뒤집을 수 있는 결정·Ruling. 없으면 "없음"}
```

## 5. 출력

bash 출력은 사용자 화면에 보이지 않는다. 최종 답변 본문에:

1. **끝내기**: §4 요약(넣은 것 포함) → `[handoff]` 결과 줄 → 완료 메시지 `HANDOFF.md 병합·커밋·<push | push 보류> | 문서 위생 <해당 없음 | PASS | 수정 N건·미해결 M건> | ROADMAP 위생 <PASS | 발견 N건> | CLAUDE.md 점검 <닿는 것 없음 | 교정 N·후보 M | 건너뜀>`.
2. **`--checkpoint`**: `[handoff]` 결과 줄 + `HANDOFF 체크포인트 [작업 이름] 저장 — 계속` 한 줄. 그리고 하던 일로 돌아간다.
3. **`--relay`(사용자가 직접)**: 끝내기와 같고(§4 요약에 「넘긴 곳」 줄 포함), 완료 메시지 끝에 ` | 발사 <착지 | 실패>` 를 붙인다.
4. **`--relay`(하네스 스킬이 부름)**: `[handoff]` 결과 줄 + `넘기고 약식 마감 — HANDOFF 병합·커밋·<push | push 보류> · 데이터 레포 <이상 없음 | push N | 할 일 N> · 발사 <착지 | 실패 — 사유>` 한 줄. 발사가 `launch_session.py` 였고 끝내 실패했으면 시작 프롬프트 파일 경로를 덧붙인다.

출력 금지: "제안합니다"·"확인해 주세요"·"다음 세션에 할까요?" 같은 사용자 행동 요구 문장, 승인 대기 항목, 열어 둔 질문. AskUserQuestion 은 이 스킬 실행 중 호출하지 않는다.
